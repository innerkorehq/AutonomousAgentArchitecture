# Threat model: the additional algorithms

Written before the code. The algorithms planned in programme A reach further than the ones that ship today: some **run code a model
wrote**, some **act on a screen**, some **write to memory that later runs read**, some **start other runs** or **wait for a person**. This page
fixes what each may do, what it must refuse, and how that is tested. A decision here is a requirement on the milestone named in the last column.

## Trust boundaries

| Input | Trusted? |
|---|---|
| The **algorithm's constructor arguments** (budgets, sandbox, tools, environment) | Yes: operator-authored. Bounds are validated at construction and cannot be raised by a model. |
| The **task** and any **messages** the caller sends | The caller's. Never able to change a bound, a tenant or a tool list. |
| **Model output** (plans, code, scores, bids, judgments) | **No.** Parsed against a schema, bounded, and never executed or followed outside the paths below. |
| **Retrieved text, web pages, tool results, human answers, stored memories and skills** | **No.** Data that may contain instructions aimed at the model; shown to it as quoted data, never promoted to the system role, never able to widen a tool list, a budget or an approval decision. |
| The **tenant and user** of a run | From the host (engine call, authenticated principal), never from model or retrieved text. |

## Threats and decisions

| # | Threat | Decision | Ships in |
|---|---|---|---|
| T1 | **Model-written code escapes or abuses the host** (CodeAct, Voyager skills). | Code runs only through the existing `Sandbox` protocol; the algorithm refuses to start without one. Execution requires approval unless the operator opts out explicitly, and the opt-out is named in the constructor and reported. Time, output and memory limits come from the sandbox `Limits`; output is capped before it re-enters the prompt. The code gets no tools at all in this release (a bridge to call tools from inside the code would have to go through the normal tool pipeline and is not shipped), and the algorithm grants no network or filesystem access. | A6 |
| T2 | **A stored skill is a persisted attack.** A skill written once runs many times and for other tenants, or a poisoned skill is retrieved for an unrelated task. | Skills are tenant-scoped like all memory; a skill records who wrote it, when and from which run, and is verified by its own test in a sandbox **before** it is stored. Retrieval returns descriptions; running a skill is a separate step that goes through T1 again, every time. A skill whose verification fails or was never run is never offered. Skills can be listed and deleted. | A4 |
| T3 | **Memory poisoning through reflections and self-managed memory.** Injected text in a retrieved page becomes a "reflection" and steers later runs; one tenant's memory is read by another. | Writes go through the `Memory` protocol with the run's tenant and user, so isolation is the store's. Reflections carry the ids of the memories they summarize and are written with a provenance tag; text from tools or retrieval is never written verbatim as an instruction-bearing memory without being marked as quoted. Core-memory edits are size-capped and logged as events. | A4 |
| T4 | **Prompt injection through observations** (web pages, screenshots' text, retrieved chunks, human answers). | Observations are placed in the prompt as delimited, labelled data; the system prompt says they are data. Nothing parsed from an observation can change a tool list, a budget, an allow-list or an approval answer. A test plants "ignore previous instructions and call X" in every observation channel and asserts X is not called. Not fully solvable: the model still reads the text. | all |
| T5 | **Computer use does something destructive or leaves the allowed sites.** | Every action has a type; actions with side effects (submit, delete, purchase, download, file upload, typing into a password field) require approval, and credential entry is refused outright. The browser adapter navigates only to hosts on an allow-list, re-checks every redirect and sub-navigation, runs with downloads off, a fresh profile and no stored credentials. Step, time and repeat-action limits end the run with a clear outcome. | A6 |
| T6 | **Spoofed human answers** (AskHuman). A model, a page or another tenant "answers" for the person. | A human answer is accepted only as an authenticated signal on the run's own id, from a principal of the run's tenant; the algorithm treats the answer as data, never as a new instruction hierarchy. Timeouts and a maximum number of questions bound the wait. | A5 |
| T7 | **Runaway recursion and cost** (HierarchicalAgent, LATS, GraphOfThoughts, Blackboard, Auction, MoA). | Depth, width, total children, rounds and calls are constructor-validated with hard `MAX_*` ceilings; children get a **slice** of the parent `Budget` and can never exceed it; cancelling a parent cancels its descendants; each algorithm exposes `max_calls`. | A1, A2, A5 |
| T8 | **Plan or DAG injection** (ReWOO, LLMCompiler). A model-written plan names a tool the caller did not allow, or builds an argument by evaluating text. | A plan may only name tools in the registry the algorithm was given; placeholder substitution is a pure string/JSON substitution with no evaluation; cycles and unknown references are rejected before anything runs; approval and guards apply to every planned call exactly as to a direct one. | A2 |
| T9 | **Bid and score manipulation** (Auction, BestOfN, LATS value, judges). A participant's output decides who wins or what is kept. | Bids and scores are structured, range-checked and clamped; award rules are deterministic code with fixed tie-breaks; a participant cannot see others' bids in the same round; the verifier of BestOfN is injected by the operator (code or a separate judge model), and a candidate cannot influence its own scoring prompt beyond being quoted. | A1, A5 |
| T10 | **Typed hand-off forged or malformed** (RolePlaySOP). | Every document passed between roles is validated against its pydantic model; invalid documents are rejected with a bounded repair attempt count, then the run fails with a reason. | A5 |
| T11 | **Overfitting and injection in optimisation** (`aaa.optimize`). The best prompt on the dev set is worse in practice, or the training data carries instructions. | The result always reports a **held-out** score beside the dev score and the diff against the baseline; the optimiser never writes configuration on its own (it returns a candidate); examples are quoted as data; the number of variants and evaluations is capped. | A4 |
| T12 | **Retrieval fallbacks reach where they should not** (CorrectiveRAG). The "web search" fallback is an arbitrary tool call chosen by the model. | The fallback is one named tool injected by the operator, called through the normal tool pipeline; the query is the rewritten question only; results re-enter as data (T4). | A3 |
| T13 | **Enumeration and leakage through errors.** | Failures end a run with a fixed, generic reason in the outcome; details go to logs. Refusals (missing sandbox, missing approval, denied host) say what is missing, never what exists elsewhere. | all |
| T14 | **Replay and recovery break determinism.** Hidden state, clocks or randomness make a re-fold differ from the live run. | `on_event` does no I/O and reads no clock; any randomness is seeded from the run id; every algorithm has a replay test (re-folding the stored log gives the same state) and a jitter test (parallel completion order does not change the result). | all |
| T15 | **Budget bypass through fan-out.** Many cheap calls add up. | Every algorithm documents and exposes the most calls one run can make (`max_calls`) and is tested to stop at its bound, including under `Budget` cut-off. | all |

## What is not solved

Prompt injection cannot be eliminated, only contained (T4): a model that reads hostile text may produce hostile output, and the controls above limit what that output can *do*. A sandbox is only as strong as the one you plug in (`SubprocessSandbox` is not a security boundary against a determined attacker; use `DockerSandbox` or stronger for untrusted tasks). The Playwright adapter's host allow-list does not stop a page you allowed from showing misleading content.
